## 二、发现与处置

### 1. [P1·已修复] `_appFrameWait` 清槽/发送顺序竞态（B-4 主项；A-7、C 附带独立发现）

- **问题**：`AwaitEnterBootloaderAck` 初版在 `session.Request()`（内含 0x12 发送）**之后**
  才清 `_appFrameWait` 暂存槽；若 0x92 应答在"发送返回→清槽"窗口内到达会被误清，
  造成假超时（设备实际已接受并复位进 BL）。与既有 `RequestAppFrame` 先清后发相反。
- **处置**：开发自查先行发现并修复（先清后发，与既有模式对齐）；B 审查独立复核确认
  同一问题（其报告基于修复前快照）。三方独立收敛于同一结论，当前代码已消除。
- **残余评估**（B-6/C）：单槽暂存的理论覆盖丢失与既有 `RequestAppFrame` 同级暴露，
  未引入新风险；超时恢复路径闭环（固件复位由其自身 UART 发送完成中断驱动，
  与主机是否收到 0x92 无关——A-6 核实，故指引①必可达）。

### 2. [P3·已修复] 会话类线程模型注释不符（B-8）

`EnterBootloaderSession` 注释「UI线程使用」与实际（升级后台线程单线程驱动，
帧经 `_appFrameWait` 锁内转交）不符 → 已改为准确描述，防止后续按 UI 线程假设误用。

### 3. [建议·已采纳] 0x03 拒绝文案补全第三分支（A-3）

固件 `fcu_boot_request()` 返回 0x03 共三分支：非 OFF / 上一请求 pending /
`fcu_rs485_tx_busy()`（主动上报占用异步 TX）。原文案漏第三分支（设备明明 OFF 却提示
"请关机"）→ 已补全三分支口径。

### 4. [建议·已采纳] 超时恢复指引两处文案缺口（C-附加核对）

- 指引①：失败退出归一化两条路径都会**关闭串口**，且 `BtnStart_Click` 有 `IsSerialOpen`
  门——"直接重新点击开始"不可达 → 已改为"重新以 9600 连接串口后再点击开始升级"。
- 指引②：过早上电（早于前置检查约 7 秒）会使旧 APP 应答 0x07 再次误入 0x12 超时分支、
  错失 3 秒连接窗口 → 已补"待状态栏出现『探测 Bootloader』后再重新上电（30 秒内）"。

### 5. [可选·决策不采纳] 视图级 OFF 门控提取为可注入纯函数（C-4）

门控为 3 行内联比较（`appStackState != 0` + FAULT 专文案），提取纯函数收益有限、
增加视图与协议层间间接层；该路径已在实施步骤 §7-4 声明为真机验证项。**按 C 标注
"可选补强"维持现状**，若后续升级页需要更多离线 UI 覆盖再统一重构。

### 6. [流程·已执行] 提交卫生（C-5）

工作区无关未跟踪物（`.mimosa/`、`.zcodeignore`、`FCU参数新增与建议清单(1).md`）
不纳入本批次任何提交，仅显式 add 本批次文件。

## 三、三路审查关键确认点摘录

- **A**：请求/应答帧逐字节与固件一致（含 `s_func_dlen[0x12]=1`、`fcu_build_set_response`
  8B 布局、CRC init/poly/字节序）；`0x87` 应答 `response[5]=stack_state` 位置正确；
  广播双保险（上位机 `DeviceAddress>=1` + 固件对广播静默）；0x92 在 `OnFrameReceived`
  中先经 `BlAppFrameReceived` 广播、不被任何会话守卫截胡；2000ms 超时取固件 1s TX 守卫
  的 2 倍裕量充分。
- **B**：等待循环锁内查状态再 `Monitor.Wait`（分片 200ms）无丢唤醒/卡死；取消上抛 OCE
  入"已取消"分支，`_busy`/`SetBlMode(false)`/CTS/按钮四路恢复完整且顺序正确；
  `blModeEntered=false` 时跳过 6s 静默语义正确；会话单线程封闭无跨线程可变状态；
  `Dispatcher.Invoke` 与模态 MessageBox 无死锁风险（WPF 消息循环继续泵队列）。
- **C**：七条要求逐条 PASS；下载链路对 master 零 diff 复核；BMS 缓存 0x11/0x91 不受
  影响（既有回归背书）；数字一致性（3 秒窗口=固件常量、30 秒=connDeadline、150ms 轮询
  周期）核对一致；离线覆盖 a–e 逐项：b/e 全离线覆盖，a/c/d 会话级离线覆盖 + 端到端真机
  待测（已在实施步骤 §7 声明）。
