# 控制应答与配方修复实施说明

## 修复方式

沿用.NET 8 WPF工程及现有协议。主要生产改动在MainWindow的控制响应处理、MainWindow.ManualControls.cs、ParameterWriteProtocol及RecipeService。

### 目标与请求隔离

之前：状态上报直接排队更新界面，风扇响应读取最新待确认值，旧回调可能作用于切换后的目标或下一次请求。

现在：帧进入接收入口时保存会话编号和不可变请求快照（创建后不再修改的请求数据），界面执行时再次校验连接和地址；手动控制额外核对快照仍属于当前请求，并且同一时刻只等待一条控制请求。

```csharp
if (_pendingLoadManualCmd == null ||
    !IsCurrentManualResponse(frame, 0x82, request)) return;
```

快照和会话编号只用于主机内部的回调隔离，没有改变线上帧。手动控制、待机周期和标定写入在结果未知后保留3秒静默窗口，避免立即复用迟到应答；待机/标定会话在静默期间仍允许诊断读取。没有事务编号的设备协议仍不能识别任意久之后才到达的同地址应答。

### 阀门时序

之前：0x0202有单独pending，手动拉载的反向发送没有互斥，双方都收到不含参数标识的0x82。

现在：0x0202进入既有普通参数事务，保持原写入报文不变；收到成功应答后请求0x0A回读，核对九项值。失败或不一致时不会显示已保存，不自动重写Flash。

### 配方

之前：写盘异常被吞掉，内存仍修改，界面提示成功；配方服务也没有初始化。

现在：初始化列表；保存先写同目录临时文件，再替换recipes.json。写入/替换失败时返回错误，并撤销本次新增、复制、改名、参数或删除操作。

```csharp
if (!SaveUserRecipes(out string error))
{
    _userRecipes.Remove(recipe);
    return (false, error, null);
}
```

保持原存储位置，避免改变已有配方来源；不迁移、不裁剪用户数据。四个超50A的系统预设下架，仅保留有效低电流预设。

## 离线验证

在仓库根目录构建：

```powershell
dotnet build 'FCU 氢燃料电池控.sln' -c Debug
```

运行真实WPF事件及假串口检查：

```powershell
dotnet run --project 'Tools/FirmwareAdaptationChecks/FirmwareAdaptationChecks.csproj' -c Debug -- --ui
```

Release配置同样运行：

```powershell
dotnet run --project 'Tools/FirmwareAdaptationChecks/FirmwareAdaptationChecks.csproj' -c Release -- --ui
```

本机使用同级`.codex-tmp/dotnet-sdk8/dotnet.exe`，不要求修改系统PATH。配方检查只操作新建临时目录，没有写真实用户配方。

## 尚需实机验证

在合适的调试条件下检查连续风扇操作、阀门写后回读、运行态手动拉载、断线/切目标、正常轮询与安全停止/BMS归还。离线测试不证明物理总线、电堆执行动作、掉电保存或固件升级可靠性。本批没有硬件，因此这些检查尚未执行。
