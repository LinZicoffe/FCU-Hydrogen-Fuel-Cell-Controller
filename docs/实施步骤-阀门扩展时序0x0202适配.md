# 实施步骤：上位机适配固件 0x0202 阀门扩展时序参数组

> 批次：feature/valve-timing-0x0202-adapt（基于 master@d5d0726）
> 固件依据：`codex/configurable-valve-timing` 分支 @ 0dbf0af（本地克隆 `D:\C_C++text\450V_FCU_latest`，未合 main）
> 核对方式：3 个独立 Agent 并行核对固件代码 + 主 Agent 交叉比对，唯一分歧（0x0202 写入响应码 0x82/0x83）已由 `fcu_protocol.h:87` 实码裁决为 **0x82**
> 文档版本：v4（第 3 轮修正：0x82/0x8E 分发结构按实码更正——消费点钉死在 0x82 专属路由；补发送失败回滚/停表与 0x0504 反向窗口披露）

## 1. 项目目标

固件 `codex/configurable-valve-timing` 分支把原先编译期写死的开机/关机阀门时序开放为 **0x0202 参数组（九项，0.1s 单位，Flash v9 持久化）**。当前上位机阀门页有 8 个时间框锁定不可编辑（对应其中部分能力）、没有 0x0202 的读写实现、「排氢关机时长」计算值里写死 +5.0s、时序预览的执行模型与固件实测语义不符。

本批完成后：阀门页全部九项时序 + 既有 0x0201/0x0E 参数可读、可改、各自独立写入、可校验，时序预览按固件真实执行语义绘制，并带 20s/30s 安全时限预算提示。

3. **读路径**：`btn_ReadValvePageParams_Click` 顺序读扩为 0x0201 → 0x0202 → 0x0601（沿用 100ms 间隔模式；0x8A 响应带参数 ID，无归属歧义）；`HandleConfigParamResponse` 的 `switch (paramTypeID)` 新增 `case 0x0202` → `ParseValveTimingParams` → 回填九框 + 重算排氢总时长；`UpdateFlowParams` 中 `tbx_ShutdownTotal = PurgeDrainHold/10 + 5.0` 的写死行改为用当前 `shutdown_empty`（0x0202 已回填值）重算，消除两处回填互相覆盖。
4. **写路径（定稿：独立按钮 + pending 为 0x0202 独享）**：新增「写入扩展时序(0x03+0x0202)」按钮（`btn_SetValveTimingParams_Click`），0x0201（`btn_SetValveParams_Click`）与 0x0E（`btn_SetFlowParams_Click`）两按钮及 `SetParameter` 公共路径**零改动**。pending 机制：

   - 消费：**消费点钉死在 0x82 专属路由**——`HandleLoadManualResponse` 的「无 LoadManual 在途回落」分支处（调用 `HandleSetParamResponse` 前按帧判定），**不得**在 `HandleSetParamResponse` 入口无条件添加（该方法被 0x8E 直连共用，入口消费会让 0x0E 的 0x8E 响应冒用 pending）；2s 新鲜度内才算 0x0202 归属（专属文案后清除并停表），超龄忽略并清除；**消费/清除统一经 `MarshalRxToUi` 编组在 UI 线程执行**（仿 SOC 先例，消除跨线程撕裂读）；0x8E 路径不触碰 pending；
   - 门禁：**仅新按钮内检查**——自身 pending 未超时则 Growl「上一条扩展时序指令尚在等待响应，请稍候」不发送；新按钮发送前同时检查既有 `_pendingLoadManualCmd` 在途互斥（与现有 0x04 类发送点一致，防 0x0504 的 0x82 被误路由）；其他既有写按钮不检查、行为不变；
   - 超时：`DispatcherTimer` 2s 单次（仿 SOC 先例），**响应到达即停表**，超时到达时清除并 Growl「2s 未收到设置响应——固件可能不支持 0x0202（需 codex/configurable-valve-timing 分支固件）或线路异常」；
   - **残余风险（已披露，见第 8 章）**：①2s 窗口内其他 0x82 写（压力走 ViewModel/ParameterManager、拉载 0x0501~0x0503 直发、风扇温度 0x06、通用 0x0B、0x0201 等）的响应先到会冒用 pending 致文案误归；②0x0504 反向时序：互斥检查是单向的，0x0202 发出后 2s 内点拉载手动，0x0202 的 0x82 会进拉载专属处理器、随后 0x0504 回落泛化路径时可能消费尚新鲜的 pending，0x0202 侧最终只剩超时 Growl。两者均仅状态文案误归、无数据破坏，不为此扩大改动面。
5. **错误处理与提示（定稿文案）**：0x82 错误码 0x03（非 OFF）→「需停机到关机状态后写入；电堆可能被自动启动抢占，可直接重试」；0x09 →「Flash 保存失败，固件已回滚内存值；**请重启 FCU 后读取全部参数核对，若读回默认值则参数页已损坏需重新配置**」（0x0A 读的是运行内存，立即回读无法发现半写坏）；0x82/0x00 成功文案尾附「可点击『读取』核对回填」；旧固件读 0x0202 返回空数据域（LEN=3）→ `HandleConfigParamResponse` 校验失败分支对 0x0202 映射专属文案「固件不支持 0x0202（需 codex/configurable-valve-timing 分支固件）」。
6. **前置校验（按钮 click 层，先例 `btn_SetPressureParams_Click` 的确认弹窗模式；组包 builder 保持纯抛异常的既有分工）**：九项 >0 且 ≤60.0s（秒值四舍五入到 0.1s，`ParseSecondsTo0P1` 既有语义）；`drain_delay < h2_delay`（严格）；预算软校验——开机两路各自 `领启+序列总长 ≤ 20s`、关机 `drain_hold+shutdown_empty ≤ 30s` 与 purge 三段总长 ≤ 30s，超限弹确认框（不阻断，文案注明固件后果：开机撞 DCDC 门控 FAULT、关机 30s 强制下电截断）。
7. **时序预览重算（定稿模型，含终关段）**：开机预览双轨并行——排水轨 t=`drain_delay` 起开①(0x0201)→关①(pause1)→开②(0x0201)→关②(pause2)→开③(third)；氢阀轨 t=`h2_delay` 起 关(c1)→开(o)→关(c2)→**常开**（HOLD_OPEN 到图尾）；状态栏给「DCDC 门控预算：两轨总长 vs 20s」。关机预览双轨并行——氢阀轨 t=0 开(open1)→关(close)→开(open2)→**终关**（DONE 固件关阀，末段标注「终关」）；排水轨 t=0 连续保持 `drain_hold+shutdown_empty`，**总长由两输入框直接求和比对 30s 预算（不经 `TryReadTimingValue` 读 tbx_ShutdownTotal，避免单项合法仅预算超限被上限误报）**；预算 30s。超限红色警示（`SetTimingError` 既有机制）。保留 100ms 量化误差说明。旧链式模型的两组交叉校验（「氢阀再次打开早于首次打开结束」「再开延时不能大于排水第二次打开时长」）随重写移除，不得保留。

- **读链路**：`btn_ReadValvePageParams_Click` 顺序发 0x0A+0x0201、0x0A+0x0601（间隔 100ms）→ `HandleConfigParamResponse`（先过 `TryValidateReadConfigResponse` 长度表校验，再 `switch (paramTypeID)`）→ `ParseValveParams`/`ParseFlowParams` 回填。无 0x0202（长度表 `GetExpectedParameterDataLength` 亦无该 ID，未注册则解析前即被拒——本批必改点）。
- **写链路**：`btn_SetValveParams_Click`→`SetValveParamHelper`（0x0201，`BuildValveParamsData` 组 12B）；`btn_SetFlowParams_Click`（独立按钮）→ 0x0E（响应 **0x8E**，`BuildFlowParamsDataFromUi`）。`SetParameter(name, func, builder)` 为即发即忘（不等响应、无回调）。**0x82/0x8E 分发结构（实码）**：`case 0x82` → `HandleLoadManualResponse`（有 `_pendingLoadManualCmd` 在途走拉载专属处理，**无在途时回落调用 `HandleSetParamResponse` 泛化文案**）；`case 0x8E` → **直连** `HandleSetParamResponse`。即 `HandleSetParamResponse` 被两个响应码共用，方法内并无「0x82/0x8E 路径」之分——0x0202 pending 的消费点必须落在 0x82 专属路由上（见写路径定稿），不得在其入口无条件添加。
- **预览**：`UpdateStartupTimingPreview`/`UpdateShutdownTimingPreview` 用链式模型（氢阀等待→开①→…），与固件实测语义（两路并行领启、氢阀先关后开再关后常开、关机氢阀领启即开）不一致；取值经 `TryReadTimingValue`（上限 9.99s）。`tbx_PurgeDrainHoldSec` 未挂输入变更事件。
- **固件侧事实**（三方核对一致，全部有 文件:行号 证据）：
  - 写帧 `AA 55 addr 03 14 02 02 | 9×u16 大端`（顺序：pause1, pause2, third, h2c1, h2o, h2c2, empty, drain_delay, h2_delay），整帧 27B；响应 `0x82` 1 字节错误码，整帧 8B。0x0E 响应为 0x8E。
  - 校验（固件实际顺序）：LEN≠20→0x05；电堆非 OFF→0x03；九项任一为 0 或 `startup_drain_delay >= startup_h2_delay`→0x02。写入成功立即整页重写 Flash（v9 镜像 368B，timing 偏移 344）；失败回滚内存并回 0x09（参数页可能半写坏，重启可能全参数回默认）。
  - 读帧 `AA 55 addr 0A 03 02 02 00`；响应 `0x8A` LEN=0x15（ID 2B+子索引回显 1B+9×u16，参数体 18B），整帧 28B；读运行内存（当前生效值）。
  - 执行语义：两路领启从 12V 上电并行计时；排水 开①/开② 时长在 0x0201，关①②/开③及氢阀三段在 0x0202；氢阀开机序列结束后常开；**关机氢阀序列 = 领启即开 open1→关 close→开 open2→终关（DONE 时固件关阀）**，无「初始关闭」段；关机排水连续时长 = `purge_drain_hold + shutdown_empty`，与氢阀 purge 并行；开机序列 20s 未完成撞 DCDC 门控 FAULT（4.0s 起检查），关机 30s 强制下电并清除残留序列；固件不校验总时长预算（u16 上限 6553.5s）。
  - 自动启动（SOC 有效且 < start_max 时每 2s）可与「读状态→写 0x0202」竞争，结果只是 0x03 拒绝（可重试），不会写坏参数。
  - 兼容性：旧固件（main）0x03 长度表=12，对 27B 帧静默丢弃（写超时）；0x0A+0x0202 回 ID 回显+空数据域（LEN=3）。新固件 0x03 长度表=0xFF 变长，不影响上位机既有 12B 的 0x0201 帧。

## 4. 技术方案

- **模型**：`ValveTimingParams` 九属性与线序一一对应（`StartPause1/StartPause2/StartThirdDuration/H2StartClose1/H2StartOpen/H2StartClose2/ShutdownEmpty/StartupDrainDelay/StartupH2Delay`），解析仿 `ParseValveParams`（大端、0.1s、ID 前缀跳过、防御 LEN/ID 不符）。
- **UI**：沿用 code-behind 直读 TextBox 模式；解锁框沿用原名（避免大范围改名）；回填统一 `UpdateValveTimingParams(ValveTimingParams)`（÷10 转秒值 + `UpdateShutdownTotal()` 重算）。
- **写路径机制（定稿）**：0x0202 独立按钮，组包 `BuildValveTimingDataFromUi`（20B：ID+9×u16），走既有 `SetParameter`（公共路径零改动）；pending 机制全量细节见第 2 章第 4 条（0x0202 独享、仅 0x82 消费、2s 新鲜度、仅新按钮门禁 + LoadManual 互斥、DispatcherTimer 超时 Growl）。
- **前置校验（click 层）**：见第 2 章第 6 条；builder 内保留硬校验（>0、≤600（0.1s）、drain<h2、抛 `ArgumentException` → 既有 `SetParameter` catch 弹错模式）。
- **预览重算**：见第 2 章第 7 条；`TryReadTimingValue` 增加 `maxSeconds` 参数（默认 9.99 保持旧行为，时序九框传 60.0），开关机预览按双轨并行模型重写，预算文案与固件口径一致（DCDC 门控 4.0s 起检查/20s FAULT；关机 30s 强制下电）。
- **关机「氢阀关闭①」框处置（定稿依据）**：固件关机氢阀序列为 开1→关→开2→终关（`fcu_valve.c` purge 相位机，领启即开阀），现有 UI 四框中的「氢阀关闭①」对应的是「运行态氢阀常开的起始状态」、无协议字段（该框 ToolTip 已自述固件无此参数）。定稿：删除该框，预览氢阀轨从 t=0 直接开 open1，终关段标注。

## 5. 影响范围

- **UI**：阀门页开机时序区（解锁 6+新增 2+标签重命名）、关机时序区（删 1+新增 1+总时长改计算）、新增「写入扩展时序」按钮、两处预览图与状态文案。
- **业务逻辑**：阀门页读写流程扩展 + `_pendingValveTimingSet` 登记机制（消费点在 `HandleLoadManualResponse` 的 0x82 回落分支，见第 2 章第 4 条；`HandleSetParamResponse` 方法本身仅在 0x0202 归属时追加专属文案分支，无 pending 时行为与旧版一致）。
- **数据/配置/接口/数据库/第三方依赖**：不涉及（设备侧 Flash v9 由固件管）。
- **通讯**：新增 0x03/0x0202（27B）与 0x0A/0x0202（→0x8A 28B）两帧；既有 0x0201/0x0E 帧不变。
- **线程/异步**：沿用 `MarshalRxToUi` 与既有串行发送；读路径三帧 100ms 间隔共约 200ms UI 冻结（既有模式，可接受）。
- **性能**：无影响。
- **兼容性**：旧固件写 0x0202 超时/读回空——九框保持默认值 + 专属降级提示；新固件 + 旧上位机不受影响。真机联调须烧录 0dbf0af 分支固件。

## 6. 项目实施步骤

## 8. 风险与注意事项

- **高风险**：预览模型重算改变现有交互（260816 需求引入的模型）；删除「氢阀关闭①」框改变关机区视觉结构——两项均已按固件实测语义定稿（第 4 章），如与现场操作习惯冲突由东哥裁决。
- **兼容性**：旧固件写超时（静默丢弃）+ 读空域降级提示；联调必须用 0dbf0af 分支固件。
- **数据风险**：0x09 后参数页可能半写坏（固件行为），文案引导「重启后回读全组核对」。
- **已披露残余风险（接受）**：①0x0202 pending 的 2s 新鲜度窗口内，其他 0x82 写（压力/拉载 0x0501~0x0503/风扇温度 0x06/通用 0x0B/0x0201，含不经 SetParameter 的直发路径）的响应先到会冒用 pending，把 0x0202 专属文案（尤其 0x09 的重配引导）误挂到别组结果上；反向则 0x0202 只剩泛化文案。②0x0504 反向时序：0x0202 发出后 2s 内点拉载手动，0x0202 的 0x82 进拉载专属处理器、0x0504 回落泛化路径时可能消费尚新鲜的 pending，0x0202 侧只剩超时 Growl。两者后果均仅限状态文案误归，无数据破坏；为消除需大改全部写路径，性价比不成立——定稿接受并在评审记录留痕。③60s 上限对 0x0201 的电堆吹扫①②两框只作用于预览读取（写路径 `ParseSecondsTo0P1` 仍允许 0.1~6553.5s，固件亦接受）——该不对称为既有行为（现状 9.99 更窄），非本批引入，登记不改。
- **回滚风险**：单分支多提交，按提交粒度回滚。
- **暂时无法确认的问题**：无（第 1 轮评审的待确认①已定稿：删除 tbx_ShutdownH2Close1，关机氢阀轨 t=0 开 open1→关→开2→终关）。
