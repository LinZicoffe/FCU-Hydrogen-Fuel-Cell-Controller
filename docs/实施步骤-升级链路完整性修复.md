> 适用对象：上位机《FCU 氢燃料电池控》（.NET 8 WPF）
> 基线：master `13e2ac3`；配套固件 APP@99aedb7 / BL@169cdf0（同事核查报告锁定版本）
> 输入：同事核查报告三项发现（我方逐条复核属实，复核证据见功能更新日志 §1）
> 约束：仅改上位机；不重写 XCP 下载协议；不动镜像守卫与参数页保护。

## 1. 修改前后行为对比

```
问题1 全镜像校验:
  修改前: PROGRAM(0) → [读回校验开关=false 跳过] → RESET → 0x81 探活 → "升级成功"
          (BL 校验字仅前 7 向量字, 传输损坏不碰向量表即成功)
  修改后: PROGRAM(0) → UPLOAD 全镜像读回比对(强制) → 一致才 RESET/探活/报成功
          (不一致 → 抛异常中止, 设备留 BL, 不重启不报成功)

问题2 XCP 超时重试:
  修改前: 命令超时 → 100ms → 直接 SET_MTA/重发
          (迟到旧应答(1B FF)可冒充新命令成功, MTA 未恢复仍报 Ok → 写错地址)
  修改后: 命令超时 → SYNCH 屏障(≤2 次×200ms, 判据 [FE 00]) → 通过才重发
          (1B 迟到应答长度不符被丢弃, 无法冒充; 屏障失败 → 中止本次下载)

问题3 AA55 应答等待:
  修改前: 每条完整帧覆盖单槽, 等待线程取走前目标应答可被心跳/上报覆盖丢失
          (前置检查误判 APP 不在线 / 0x92 拒绝退化成泛化超时); 且不核对应答地址
  修改后: 收帧入口按事务过滤(功能码+地址), 非本事务帧不入槽不覆盖;
          RequestAppFrame 补地址核对(应答须与请求同地址, 广播除外)
```

## 3. 关键实现语义

1. **读回校验时点**：必须在 PROGRAM(0) 之后（此前尾块可能仍缓冲在 BL RAM bootblock）；
   比对跳过镜像偏移 0x1D8-0x1DB（BL 已覆写校验字，与文件占位值不同属预期）——沿用既有实现。
2. **屏障判据**：`!Timeout && Data==[FE 00]`。SYNCH 正常应答本身就是错误包（Ok=false），
   不能用 Ok 判定；在途迟到 1B 0xFF 因长度不符（expectedLen=2）被丢弃，无法冒充；
   非零错误码 [FE xx] 不算通过，防旧命令错误应答冒充。**显式错误响应不算超时**——
   BL 已应答说明链路同步，直接重试，无需屏障。
3. **等待槽线程模型**：`Offer` 由串口接收线程调用；`Begin/WaitOne/End` 由升级后台线程单线程
   驱动（一次只存在一个等待事务），与 `EnterBootloaderSession` 会话封闭口径一致。
   过滤器在发送请求**之前**登记（对齐既有"先清后发"序）；所有退出路径 `finally End()`。
4. **地址核对**：`RequestAppFrame` 过滤器要求应答 `frame[2] == request[2]`（单播）；
   地址 0（广播请求）不过滤地址。`EnterBootloaderSession` 内部本就核对地址，双保险保留。

## 4. 离线验证

- Debug 构建 0 警告 0 错误（sln + checks 工程）。

  **PASS 434 项**（413 + 21 新增）。新增检查含同事核查报告两个复现场景的转绿验证：
  - 问题 3 复现（心跳覆盖 0x92 拒绝应答）→ `AppFrameWaitSlotChecks` #8：心跳干扰下

    被丢弃，屏障不通过。

## 5. 待板测清单（新增，叠加在软件进入批次 §7 的 7 项之上）

1. 强制读回校验全流程：正常升级中 UPLOAD 比对通过 → 成功；实测新增耗时（预估 1 分钟量级）。
2. 读回不一致中止：人为制造（如中断后部分写入再校验）→ 确认不 RESET、不报成功、设备留 BL。
3. SYNCH 屏障真实触发：升级中拔串口几秒再插 → 超时 → 屏障失败 → 中止文案与"可直接续升"路径。
4. 屏障通过场景：制造一次写块超时（如短暂干扰）后恢复正常 → 屏障通过 → 续写成功。
5. 心跳干扰回归：9600 前置检查/0x12 握手期间设备存在主动上报 → 不再出现误判/假超时。
6. 既有 7 项板测（软件进入批次 §7）全部仍待真机执行。
