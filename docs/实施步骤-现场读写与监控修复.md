# 现场读写与监控修复实施步骤

## 范围与依据

用户已授权先修复上位机。以 master@fd68961 和下位机 fix/valve-drive-polarity@216edd2（与 main@0c8dc1d 文件相同）为依据；用户提供的 HEX 已核验关键阀门极性、500ms 拉载上报及 k/b 反算功能，但未据此声称完整构建与 Git 逐字节一致。

## A 监控数据

- 对 0x87 固定 26 字节、0xF2 固定 14 字节，核验帧头、功能码、实际长度与 CRC。
- 异常帧保留最近有效读数，显示失败/等待/超时信息；真实零读数仍正常显示 0。
- 断线、目标变化及升级后拒绝旧 Dispatcher 队列响应，等待新设备数据；广播探针不覆盖目标设备遥测。
- 明确“扫描峰值电流”不是手动设流目标，不改协议字段、测量倍率或功率数据来源。

## B 普通参数写入

- 建立普通参数写入单事务：发送成功 → 等设备确认 → 读取对应参数 → 按固件布局比较全部字段。0x0501 写帧的 count 不在回读体内，单独规范化。
- 接入压力 0x0101、阀门 0x0201、DCDC 0x0301、风扇 0x0401、时序/控制/周期 0x0501/02/03、流程 0x0601、通用 0x0901 等普通参数。已有 0x0202/0x0302/0x0902/SOC 专用事务保留。
- 事务期间暂停自动普通查询并封锁其他普通发送；等待已经在途的监控/BMS 请求结束后再写；不重试写入。
- 持久显示发送失败、设备拒绝、保存失败、响应超时、回读不一致或成功。手动读取不能抢在待确认写入前覆盖编辑值。
- 断线、切目标、升级及关闭清理事务；安全停机和 BMS 归还仍可发送。

## C 压力参数与验收

- 把整帧实际参与校验的高压红/黄警阈值展示在压力设置区域，保持既有单位与固件校验；不自动改阈值迎合量程。
- 对“首次未读取确认框”的原有语义给出说明，写入结果统一通过持久结果区反馈。
- Debug 构建与现有 --ui 检查必须通过；新增假串口验证异常帧保持数据、会话切换、发送失败、ACK 错误/超时、回读不一致、重复写入、轮询互斥及安全旁路。
- 检查实际渲染的设置、监控、压力页面，记录真机边界。每步独立审查后提交，最后三个全新 Reviewer 并行终审。
