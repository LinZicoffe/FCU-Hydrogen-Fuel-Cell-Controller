# 实施步骤-低压分级泄压保护适配（上位机）

> 依据：下位机仓库 `450V_FCU` 分支 `codex/low-pressure-relief-protection`（提交 a5a8d63 实现、9296c2f 测试、004b1c2/5bf30eb 协议文档，基于 main@ed88e43，含 PR#18 beforepined 合并与 PR#19 压力传感器电压换算修正 4a2196e）。下位机两仓库（450V_FCU、Boot-For-FCU）只读，本次不修改任何嵌入式代码。

## 1. 项目目标

下位机新增「低压分级泄压保护」功能（2026-10-08 扩展，协议 §6.3）：运行态低压 >80KPA 时固件自动开排水阀泄压并上报 WARNING 报警 0x000C，压力恢复上报状态 0x0105；低压上下限默认值由 35/65 KPA 改为 20/100 KPA，上限保护改为连续 3 个 100ms 快采样判定。上位机（本仓库）需同步适配：识别新增报警/状态类型、对齐压力默认值与文案，使两机语义一致；随后发布 V1.9.1 双安装包。

## 2. 实施范围

### 本次包含

1. 压力参数页低压默认值 35/65 → 20/100（含注释出处更新）。
2. 低压下限/上限 ToolTip 语义更新（上限改 100ms 快采样×3 判停机、新增 80KPA 固定泄压警示线说明）。
3. 报警码表新增 0x000C「低压超限泄压警示」，数值按 KPA 原值格式化。
4. 状态码表新增 0x0105「低压泄压保护」，0xF1 上报显示「未触发/泄压中」而非裸数字。
5. 版本号 V1.9.0 → V1.9.1，README「更新日志」登记，制作标准 + 众赢普惠两个安装包（旧安装包保留不删）。

## 4. 技术方案

纯上位机「码表 + 默认值 + 文案」适配，不新增帧结构：

- 数据流不变：固件 0xF0/0xF1 主动上报 → `ProtocolHandler` AA55 状态机 → `OnFrameReceived` 分发 → `ResponseParser.ParseAlarmInfo/ParseStateChange`（定长解析，天然兼容新码值）→ `ShowAlarmMessage/ShowStateChange` 显示。适配点全部在显示/预填层。
- 0x000C 归入压力类数值格式化分组（KPA 原值），复用 `GetAlarmValueDescription()` 现有 switch 分支。
- 0x0105 在 `ShowStateChange()` 增加专用分支，将 0/1 映射为「未触发/泄压中」（仿照 `GetStackStateName` 的做法），恢复上报显示「泄压中 → 未触发」，语义上与协议 §6.3「压力恢复消息不等于告警清除」一致——告警 Growl 仍保留，仅状态行提示恢复。
- 默认值仅影响 UI 预填；参数写入仍由用户在压力页手动触发，帧格式/校验不变。

## 5. 影响范围

- **UI**：压力页两个 ToolTip 文案；状态变更提示文案（0x0105）；报警 Growl 显示新类型名。不新增控件、不改布局。
- **业务逻辑**：无状态机/流程改动；仅码表映射。
- **数据**：无持久化数据变化（默认值不落盘，除非用户写入参数）。
- **通讯**：不改任何帧构造/解析/校验；仅新增码值的显示映射。
- **配置/接口/数据库/PLC/第三方依赖/线程异步/性能**：不涉及。
- **兼容性**：旧固件不发送 0x000C/0x0105/0x4842，上位机新增映射为死分支，无影响；新固件 + 旧上位机（V1.9.0）会显示「未知报警」，且 0x0105 未知状态与 0x4842 心跳（每 5s 一帧「未知状态」刷屏）并存，本次适配一并消除。写入 20/100 到旧固件（V1.2）仍可通过其校验（35/65→20/100 满足下限<上限且≤量程 250），但会放宽旧固件扫描式上限告警阈值——发版说明中提示。
- **升级功能/许可证/双协议隔离**：不涉及。

### 步骤 4：状态码表新增 0x0105、0x4842 心跳静默与显示分支

**目标**：0xF1 上报 0x0105 时显示「低压泄压保护: 泄压中 → 未触发（或反向）」；0x4842 通讯心跳（每 5s 一帧）静默忽略，不刷状态栏。

**修改位置**：`FCU 氢燃料电池控/Models/ProtocolModels.cs`：`StateChangeData` 类注释（~:390 补 0x0105）与 `GetStateTypeName()`（~:414 后新增 `0x0105 => "低压泄压保护"`）；`FCU 氢燃料电池控/MainWindow.xaml.cs`：`ShowStateChange()`（:4072 起）新增 0x0105 专用分支。

**修改内容**：仿照 `GetStackStateName` 新增静态方法 `GetLowPressureReliefStateName`（0/1 → 「未触发/泄压中」，置于 `GetStackStateName`（:3589）旁），`ShowStateChange()` 新增 0x0105 分支调用之，`UpdateStatus($"状态变更：低压泄压保护: {旧} → {新}")`；不刷新 `StackState`（非电堆状态）。同函数内新增 0x4842 心跳分支：`if (StateType == 0x4842) return;`（注释注明「RS485 通讯心跳(e3bb0b6, 每5s)，静默忽略防止刷屏」，不做任何 UpdateStatus/Growl）。`GetStateTypeName()` 不为 0x4842 添名（静默路径不经过名称映射）。

**实现逻辑**：固件 0xF1 数据域 `01 05 00 01`（触发）/`01 05 01 00`（恢复）与现有 4 字节定长 `ParseStateChange` 匹配，无需改解析器。恢复消息只提示状态恢复；0x000C 的 Growl 警示不因此清除（后台人工消除，与协议 §6.3 一致）。心跳 0x4842 是本分支固件引入的周期性 0xF1 流量（旧配对固件无此帧），不过滤会每 5s 以「未知状态: X → Y」覆盖状态栏——静默忽略后链路存活判断仍走既有 0x87 轮询命中机制，心跳不承担 UI 职责。

**依赖**：无。

**风险**：无。

**验证方式**：以临时调试入口（验证后移除，验证代码不得进入提交）将触发帧 `AA 55 01 F1 04 01 05 00 01 04 60` 与恢复帧 `AA 55 01 F1 04 01 05 01 00 27 70`（addr=0x01，CRC 已核对；addr 变化时 CRC 需重算）喂入状态机，核对状态栏文案；再喂心跳帧 `AA 55 01 F1 04 48 42 00 01 01 B6`，确认状态栏**无任何变化**；确认 0x0101 分支行为不变。

**完成标准**：0x0105 触发/恢复两方向文案正确；0x4842 心跳帧静默（无状态栏/Growl 输出）；0x0101 分支不回归；0x0102-0x0104 为协议表预留映射，其映射未被改动以代码检视确认。固件 0xF1 发送点以 `git grep FCU_FUNC_REPORT_STATUS`（固件分支）核对，共三处：0x0101（fcu_control.c）、0x0105（fcu_control.c）、0x4842 心跳（Core/Src/main.c）。
