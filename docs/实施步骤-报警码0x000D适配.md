# 实施步骤：上位机适配固件报警码 0x000D（电堆温度采样无效）

> 批次：feature/alarm-0x000d-adapt（基于 master@e61c312）
> 固件依据：450V_FCU 仓 origin/main@6ed7c7b（2026-10-09 修复批次 8cfd00f/37c6549 引入，PR#21 随后合入）
> 文档版本：v1（impl-doc-review 流程产出）

## 1. 项目目标

固件 main 已新增报警码 **0x000D（电堆温度采样无效，FCU_ALARM_TEMP_SENSOR_FAULT）**：PT1000 断线/短路（采样电压 ≤0.1V 或温度超 -40~150℃，瞬时+滤波双校验）时，固件拒绝启动（0x88 回错误码 0x03）或在 STARTING/RUNNING 中立即 FAULT 停机，并通过 0xF0 主动上报（level=CRITICAL 0x04，value=0x0000）。

当前上位机 `AlarmData.GetAlarmTypeName()` 对 0x000D 返回「未知报警」、数值描述落入默认分支输出裸值「0」。本次修改使上位机正确识别并展示该报警，达到与 0x000C（低压超限泄压警示，V1.9.1 已适配）一致的展示质量。

## 3. 当前项目现状

- 报警链路（已通，无解析改动）：串口 RX → `ProtocolHandler` AA55 状态机 → `MainWindow.OnFrameReceived` case 0xF0 → `HandleAlarmReport`（`MainWindow.xaml.cs`，方法名可 grep 定位，行号随提交漂移不写死）→ `ResponseParser.ParseAlarmInfo`（0xF0 数据域 5 字节：type 2B 大端 + level 1B + value 2B 大端）→ `MarshalRxToUi` → `ShowAlarmMessage`（`MainWindow.xaml.cs`）。
- `ShowAlarmMessage` 按 `AlarmLevel` 泛化分发 Growl：0x03/0x04 → `Growl.Error`，0x02 → `Growl.Warning`，其余 → `Growl.Info`；并更新 `StatusMessage`。**等级分发无需改动**，0x000D（CRITICAL=0x04）自动走 Error。
- 唯一缺口在 `AlarmData`（`Models/ProtocolModels.cs:289-383`）两张码表：
  - `GetAlarmTypeName()`：已收录 0x0001~0x000C，缺 0x000D → 「未知报警」；
  - `GetAlarmValueDescription()`：压力类（0x0001/0x0003/0x000A/0x000C）KPA 原值、温度类（0x0002/0x0009）×10 有符号、电压类（0x0005/0x0006）×10、0x0008 位图解码、0x0004 RPM、0x000B SOC%，0x000D 落入 `_ =>` 裸值「0」。
- 固件侧权威定义（origin/main 已核实）：
  - `App/Inc/fcu_control.h:68`：`FCU_ALARM_TEMP_SENSOR_FAULT = 0x000D /* 电堆温度采样无效 */`；
  - 触发点① `App/Src/fcu_control.c:435-438`：STARTING/RUNNING 100ms 安全检查，`stack_temperature` 非有限（NaN）→ 清风扇手动 + 强制全速 + `fcu_control_set_fault(0x000D, 0U)`；
  - 触发点② `App/Src/fcu_control.c:449-450`：启动流程采样供电开启后 30s 无新采样批次 → `fcu_control_set_fault(0x000D, 0U)`；
  - `check_start_condition` 温度 NaN 拒绝启动（0x88 回 0x03，非报警帧）；
  - value 恒为 `0U`，level 恒为 CRITICAL(0x04)（set_fault 路径）。

## 4. 技术方案

在 `AlarmData` 两张码表各加一个 switch 臂，完全复用 0x000C 批次的适配模式（a208c6d feat(C)）：

- 名称：`0x000D => "电堆温度采样无效"`，与固件枚举注释「电堆温度采样无效」逐字一致，不自行改写（历史码表命名均对齐固件注释）。插入位置：名称表插在 0x000C 独立臂之后；数值表插在 0x000B（充电异常）臂之后、`_ =>` 兜底臂之前——硬约束是新臂必须位于 `_ =>` 之前（数值表中 0x000C 位于压力合并臂「0x0001 or 0x0003 or 0x000A or 0x000C」内，并非独立臂）。已核实两张表均无码位冲突。
- 数值描述：`0x000D => "采样无效（PT1000 断/短路）"`，臂旁加行内注释「value 固定 0，无物理量纲」（风格对齐 0x0008 位图臂）。理由：value 固定 0x0000，输出「0」会误导用户当成有效测量值；且此时 0x87 温度字段按固件 NaN→0 规则也上报 0.0℃，两处都须以本报警码为准而非数值。不显示单位（无物理量纲）。
- 等级/通道：`ShowAlarmMessage` 泛化逻辑已覆盖（0x04 → Growl.Error「严重报警」+ 状态栏「收到报警：电堆温度采样无效」），无需改动。
- 同步更新 `GetAlarmValueDescription()` 头部口径注释：新增一行 0x000D 说明（触发条件、value=0、NaN→0 联动），并注明固件依据文件（枚举名 grep 定位，行号随提交漂移不写死触发行号，仅写 `fcu_control.c` 安全检查/启动等待两处语义位置）。

数据流不变：0xF0 帧 → ParseAlarmInfo（不动）→ 码表映射（本次唯一改动点）→ Growl/状态栏。

## 7. 测试与验证方案

1. **编译验证**：`dotnet build "FCU 氢燃料电池控.sln" -c Debug`，0 警告 0 错误。
2. **静态帧验证**（帧级推演，参照低压批次 0x000C 的验证方法）：构造 0xF0 报警帧，完整期望字节 **`AA 55 01 F0 05 00 0D 04 00 00 1D 26`**（数据域：type=0x000D、level=0x04、value=0x0000；CRC=0x1D26 高字节在前，按 `ProtocolHandler.CalculateCRC16` 现行算法——初值 0xFFFF、多项式 0x1021、无反射、无异或输出，即 CRC-16/CCITT-FALSE，已经独立双实现交叉验证），核对：
   - `ParseAlarmInfo` 解析得 AlarmType=0x000D/AlarmLevel=0x04/AlarmValue=0x0000；
   - `GetAlarmTypeName()` →「电堆温度采样无效」；
   - `GetAlarmLevelName()` →「严重」；
   - `GetAlarmValueDescription()` →「采样无效（PT1000 断/短路）」；
   - `ShowAlarmMessage` 走 `case 0x04` → `Growl.Error`。
   CRC 计算与字节序（大端）按 `ProtocolHandler` 现行实现核对。
3. **回归确认**（抽验帧完整字节，CRC 算法同上）：
   - 0x000C 回归帧 `AA 55 01 F0 05 00 0C 02 00 50 83 C7`（WARNING + 80KPA 泄压线典型值）→ 名称「低压超限泄压警示」、数值「80 KPA」、Growl.Warning；
   - 0x0002 回归帧 `AA 55 01 F0 05 00 02 03 FF CE 77 25`（ERROR + 0xFFCE）→ 数值「-5.0 ℃」（有符号还原）；
   - 0x0001 帧展示不变；0x0007（无单位定义）与 0x000E（未收录码）均走 `_ =>` 兜底输出裸值；
   - git diff 确认改动仅两张码表新增臂 + 注释，既有分支零改动。
4. **真机观察项**（本批不做，登记待联调）：拔 PT1000 触发 0x000D 时 Growl 文案、0x87 温度显示 0.0℃ 与报警联动、启动拒绝时 0x88 错误码 0x03 的提示文案。触发操作要点：拔线后固件经瞬时+滤波双校验判 NaN（运行中约 100ms 安全检查周期即触发），启动路径则有 30s 采样超时窗口。注意：现有启动失败 0x03 文案（`BuildStartFail03Message`）枚举「低压超限 / 温度≥风扇上限 / SOC 拒启」三条路径，新固件下温度采样无效（NaN）是第四条返回 0x03 的路径，现有文案与注释已过时；是否扩充该文案留待联调批次决定（0xF0 报警链路不受影响，不属本批范围）。
